# 改善ループ・プロトコル（面白さチューニング）

目的: 面白さ指標を改善する。クリア率はガードレール（45〜65%を維持）。
指標の重要度はすべて同等（2026-07-19 ユーザー決定）。

## 1イテレーションの手順

1. **選ぶ** — 下のバックログ（または新案）から改善案を1つだけ選ぶ。1周1変更が鉄則。
2. **実装する** — 変更行には `// fun:` コメントを付ける（`// balance:` と区別）。
3. **計測する** — `node test/headless.js 40 400000`（seed固定でA/B比較。2026-07-20から40ep標準: 20epはCLEARノイズ±10ppで採否判定に不足）。
4. **判定する** — 下の判定基準で採用/棄却を決める。
5. **記録する** — 採用なら変更をコミットし `loop-log.md` に追記。棄却なら revert して理由を `loop-log.md` に追記（棄却も学習データ）。

## 判定基準（2026-07-20改定: クリアタイム目標とAI/ゲーム変更の区別を追加）

- **対象の区別（重要）**:
  - **ゲーム変更**（ルール・バランス・新要素）: AIを固定したまま計測。ガードレール＋FUNスコアで判定。
  - **AI戦略変更**: 目標は「生存率＋クリアタイム」（2026-07-20ユーザー決定。生存率だけだと全て自力破壊が最適解になるため）。CLEARとクリアタイム(tick)で直接判定し、CLEARガードレールの上限超過は「AIが上手くなった」なので棄却理由にしない。採用したらリファレンス計測を取り直す。
- **ガードレール（ゲーム変更に必須）**: CLEAR率が**リファレンス比±10pp以内**（2026-07-20に絶対帯45〜65%から変更。AI性能が上がると絶対帯は誤判定するため）、即死率(HP死のうち)=0%。
- **採用条件（ゲーム変更）**: 5カテゴリ等重みの一次結合 **FUNスコア > 0**。
  - 各指標の対リファレンス変化率(%)を「目標方向が正」になる符号で取り、±100%にクリップ
  - カテゴリ内の複数指標は平均 → 5カテゴリを平均したものがFUN
  - 計算: `node test/funscore.js <リファレンス.txt> test/<variant>.txt`
- **現行リファレンス**: `test/iter10-ai-tempo-2026-07-20.txt`（iter9採用エンジン+iter10採用AI、40ep、クリアタイム指標入り。CLEAR=73%, クリアタイムmedian=77,989tick）。
- 履歴: 旧基準「全指標が許容幅内」→FUNスコア(2026-07-19)→本改定。旧リファレンス: baseline-2026-07-19.txt(20ep) → baseline40-2026-07-20.txt(40ep) → baseline-ai-2026-07-20.txt(クリアタイム入り)。

## 指標と目標方向（ベースライン 2026-07-19、20エピソード）

| 指標 | ベースライン | 目標方向 | 理由 |
|---|---|---|---|
| 緊張感: nearDeath/100F | 10.5 | 維持〜微増 | ピンチは面白さの源泉。ただし死亡増で稼ぐのは不可 |
| 緊張感: 蘇生発動/100F | 61.2 | **減らす** | 蘇生連打は「死んでも平気」＝緊張感の希薄化 |
| 単調さ: 無イベント階 | 7.7% | 減らす | 何も起きない階は退屈 |
| 成長: 最大Lv停滞 | 18.4階 | **減らす** | 18階もレベルが上がらない区間は成長実感ゼロ |
| 理不尽: bigHit/100F | 1.2 | 維持（低いまま） | 対処不能な大ダメージは理不尽 |
| テンポ: ticks/floor | 105.2 | 微減 | max1floor=1666 のような間延び階を潰す |

参考: CLEAR=55%、死亡フロア p25=34 / p50=50 / p75=946（序盤か終盤に二極化）。

## バックログ（ベースライン分析から）

- [ ] **序盤の即死帯（21〜50F）の緩和** — 死亡の半数が50F以前。序盤で運ゲー死するのは理不尽寄り。
- [ ] **蘇生経済の引き締め** — 蘇生/100F=61は「蘇生で殴り抜ける」状態。蘇生入手率か効果を調整し、代わりに回復系を厚くする等。
- [ ] **Lv停滞区間の解消** — XPカーブか敵経験値の見直しで最大停滞18階→10階以下へ。
- [ ] **間延び階の対策** — 1階に1666ティックかかるケースの原因調査（探索迷子か敵殲滅コストか）。
- [ ] **無イベント階の削減** — 箱・敵配置の最低保証、またはフロアイベントの追加。

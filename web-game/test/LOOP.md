# 改善ループ・プロトコル（面白さチューニング）

目的: 面白さ指標を改善する。クリア率はガードレール（45〜65%を維持）。
指標の重要度はすべて同等（2026-07-19 ユーザー決定）。

## 1イテレーションの手順

1. **選ぶ** — 下のバックログ（または新案）から改善案を1つだけ選ぶ。1周1変更が鉄則。
2. **実装する** — 変更行には `// fun:` コメントを付ける（`// balance:` と区別）。
3. **計測する** — `node test/headless.js 20 400000`（seedは固定済みなのでベースラインと同一マップ列でA/B比較になる）。
4. **判定する** — 下の判定基準で採用/棄却を決める。
5. **記録する** — 採用なら変更をコミットし `loop-log.md` に追記。棄却なら revert して理由を `loop-log.md` に追記（棄却も学習データ）。

## 判定基準（2026-07-19改定: ユーザー指示によりFUNスコア方式へ）

- **ガードレール（必須）**: CLEAR率 45〜65%、即死率(HP死のうち) = 0% を維持。逸脱したら即棄却。
- **採用条件**: 5カテゴリ等重みの一次結合 **FUNスコア > 0**（＝ベースラインを上回る）。
  - 各指標の対ベースライン変化率(%)を「目標方向が正」になる符号で取り、±100%にクリップ
  - カテゴリ内の複数指標は平均 → 5カテゴリを平均したものがFUN
  - 計算: `node test/funscore.js test/baseline-2026-07-19.txt test/<variant>.txt`
- 旧基準「全指標が許容幅内」は廃止。参考: 旧3イテレーションを新基準で再採点しても FUN = -10.5 / -7.5 / -13.2 ですべて棄却のまま（判定の連続性は保たれている）。

## 指標と目標方向（ベースライン 2026-07-19、20エピソード）

| 指標 | ベースライン | 目標方向 | 理由 |
|---|---|---|---|
| 緊張感: nearDeath/100F | 10.5 | 維持〜微増 | ピンチは面白さの源泉。ただし死亡増で稼ぐのは不可 |
| 緊張感: 蘇生発動/100F | 61.2 | **減らす** | 蘇生連打は「死んでも平気」＝緊張感の希薄化 |
| 単調さ: 無イベント階 | 7.7% | 減らす | 何も起きない階は退屈 |
| 成長: 最大Lv停滞 | 18.4階 | **減らす** | 18階もレベルが上がらない区間は成長実感ゼロ |
| 理不尽: bigHit/100F | 1.2 | 維持（低いまま） | 対処不能な大ダメージは理不尽 |
| テンポ: ticks/floor | 105.2 | 微減 | max1floor=1666 のような間延び階を潰す |

参考: CLEAR=55%、死亡フロア p25=34 / p50=50 / p75=946（序盤か終盤に二極化）。

## バックログ（ベースライン分析から）

- [ ] **序盤の即死帯（21〜50F）の緩和** — 死亡の半数が50F以前。序盤で運ゲー死するのは理不尽寄り。
- [ ] **蘇生経済の引き締め** — 蘇生/100F=61は「蘇生で殴り抜ける」状態。蘇生入手率か効果を調整し、代わりに回復系を厚くする等。
- [ ] **Lv停滞区間の解消** — XPカーブか敵経験値の見直しで最大停滞18階→10階以下へ。
- [ ] **間延び階の対策** — 1階に1666ティックかかるケースの原因調査（探索迷子か敵殲滅コストか）。
- [ ] **無イベント階の削減** — 箱・敵配置の最低保証、またはフロアイベントの追加。
